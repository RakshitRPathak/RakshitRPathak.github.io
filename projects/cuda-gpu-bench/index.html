cuda-gpu-bench

Hand-written CUDA kernels for vector add, matrix multiply and sum reduction, benchmarked on a T4 and explained instruction by instruction.

Complete

The problem

Each kernel answers one question a GPU performance engineer asks: how much does shared-memory tiling help, and what does synchronization cost (atomics vs shared-memory tree vs warp shuffles)?

How it works

  1. kernel source
  2. CPU emulator tests
  3. nvcc (sm_75)
  4. CPU reference check
  5. CUDA-event timing
  6. PTX instruction counts
  • Naive and shared-memory tiled matrix multiply, plus three reductions: contended atomics, shared-memory tree and warp shuffle.
  • Built with nvcc for sm_75 and run on a Tesla T4; every kernel passes its CPU-reference check before it is timed.
  • Tiling gained 1.5×, not the 16× the load count suggests: the naive kernel's loads already go through the read-only cache. Register tiling is the next step.
  • A CPU emulator of threads, blocks, shared memory, barriers, atomics and warp shuffles runs the kernel logic on any machine; deliberately broken kernels are all caught.

Built with

CUDAC++PTXThreadSanitizer
