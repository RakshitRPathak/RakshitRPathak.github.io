Projects/Systems and compilers

minic

A dependency-free compiler for a small imperative language with functions and recursion: a bytecode back end, plus an SSA intermediate representation with six optimization passes, checked by a differential fuzzer.

Complete

Pipeline

  1. 1source
  2. 2lexer
  3. 3parser (AST)
  4. 4semantic analysis
  5. 5AST optimizer
  6. 6bytecode + backpatching → stack VM
  7. 7or: SSA IR → IR optimizer → IR interpreter

The problem

Built to understand every stage between source text and execution, including the parts textbooks skip: error messages with line numbers, forward jumps, and keeping optimizations from changing behaviour.

How it works

  • Hand-written lexer with one character of lookahead; recursive-descent parser building an AST.
  • Constant folding and dead-branch and dead-loop elimination. Folding shares its arithmetic code with the VM, so both agree on overflow and division.
  • Forward jumps are resolved by backpatching, the same problem linkers solve with relocations.
  • Semantic analysis runs before optimization, so removing dead code can never change which programs compile.
  • Functions with parameters, locals and recursion: the VM keeps a stack of call frames and reports runaway recursion instead of crashing.
  • A second back half lowers the AST to three-address code in SSA form over a control-flow graph, built directly in SSA with the algorithm of Braun et al.
  • Six IR passes run to a fixed point: constant propagation, branch folding, phi simplification, global value numbering over the dominator tree, dead code elimination and block merging. Calls, prints and any division that could fail are never removed.
  • A differential fuzzer generates random programs and requires identical output from the bytecode VM and the IR, optimized and not. It was checked against seven hand-planted optimizer bugs and reports each one.
