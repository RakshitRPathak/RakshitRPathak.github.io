PTXForge

A closed-loop autotuner for a fused GEMM + bias + GELU CUDA kernel, with custom MLIR passes for epilogue fusion and shared-memory padding. On a T4 it reaches 85.6% of cuBLAS.

In progress

The problem

Choosing tile sizes and shared-memory layout for a GPU kernel by hand is slow, and a wrong guess can cost several times in throughput. PTXForge searches the configuration space with a cost model, measures every candidate on the GPU, and keeps a trace of each decision.

How it works

  1. linalg
  2. fuse-epilogue
  3. tile (transform schedule)
  4. bufferize
  5. pad-workgroup-memory
  6. gpu → nvvm → llvm
  7. PTX
  8. CUDA runner
  • Header-only C++20 core: a 3,610-config tile search space, a roofline cost model (arithmetic intensity, register caps, occupancy, wave quantization) and closed-loop search.
  • One bank-conflict model is shared by the tuner and the MLIR padding pass, so the compiler and the cost model agree on what conflict-free means.
  • Advisors (none, random, rules, knowledge graph, external LLM) propose configs; every suggestion is validated in C++ before it runs.
  • The CUDA runner loads PTX in-process through the Driver API, checks each candidate against an fp64 reference, and times it next to cuBLAS in the same run.
  • The first T4 run showed the cost model ranks near-optimal configs badly (Spearman ρ = −0.67). The tuner still got to 85.6% of cuBLAS because it keeps the measured best, which is the argument for closed-loop measurement.
