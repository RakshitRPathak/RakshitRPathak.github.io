agentic-bug-repair

Takes a Java repository with failing tests and tries to produce a verified fix as a pull request, in the style of SWE-agent systems but small enough to read in a sitting.

Complete

The problem

A failing build usually needs a person to find the faulty method and try fixes by hand. The agent automates that loop and only publishes a diff that passes every test on a clean checkout.

How it works

  1. failing build (webhook or CLI)
  2. code graph
  3. fault localization
  4. patch synthesis
  5. sandboxed tests
  6. critic (≤ 3 rounds)
  7. clean-checkout re-check
  8. pull request
  • The JDK compiler API parses the repository into a code graph with call, import, inheritance and field-write edges.
  • Fault localization combines test failures, the graph and text retrieval to rank suspect methods.
  • Candidate diffs run in an isolated sandbox; failures are fed back for up to three correction rounds.
  • A GitHub webhook can trigger runs, and a dashboard shows the state machine, the diff and telemetry. State-changing calls require same-origin JSON on a loopback host.

These numbers are not comparable to SWE-bench scores.
